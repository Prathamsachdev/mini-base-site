The complete reference for mini-base — what it does, how to set it up as a CLI or an SDK, and every feature it supports.

What mini-base actually does

mini-base turns a Postgres database into a REST API automatically. Point it at a connection string, and it reads your schema — tables, columns, primary keys, foreign keys — then instantly exposes a full CRUD REST API for every table. No code, no route files, no ORM models to write by hand.

Under the hood, it does three things when it starts up:

  1. Connects to your Postgres database using a connection string you provide.
  2. Introspects the schema — it queries Postgres's own information_schema and pg_catalog system tables to discover every table, its columns, its primary key, and its foreign key relationships. You don't declare any of this yourself.
  3. Generates REST routes for every table it found — GET, POST, PATCH, DELETE — building safe, parameterized SQL from the query parameters a client sends.

If you have a users table and a posts table with a foreign key posts.user_id → users.id, mini-base gives you a working API for both — including fetching a user with their posts nested inside the response — without you writing a single line of route or query code.

Use cases

  • Prototyping and internal tools — you have a Postgres database and need an API in front of it right now, without spinning up a backend project.
  • Admin panels / internal dashboards — point an internal tool builder at the REST API instead of giving it raw database credentials.
  • Small teams that don't want a hosted BaaS — you like the “instant API from schema” idea, but you already have your own Postgres instance and don't want to migrate to a hosted platform.
  • Learning how tools like PostgREST work — a small, readable codebase demonstrating schema introspection → dynamic, safe SQL generation.
  • Embedding into an existing Node app — via the SDK, mount the generated API inside an app you already have, and layer your own auth on top using hooks.

What mini-base is NOT

mini-base does not include authentication or authorization as a built-in system (you bring your own via hooks), realtime subscriptions, file storage, edge functions, or a hosted dashboard. It is only the schema-to-REST-API generation layer — the equivalent of self-hosting PostgREST, with some extra conveniences (hooks, config files, safer defaults) built in.
