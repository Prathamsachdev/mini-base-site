Config & access control

Readonly mode

bash
mini-base --db postgres://... --readonly

When enabled, POST, PATCH, and DELETE routes are never registered at all (not just rejected at runtime) — a request to a write route returns a plain 404, as if the route never existed. Useful for exposing a read-only API, e.g. for a public-facing dashboard.

Include/exclude tables

Available via the config file or the SDK (not a CLI flag):

js
// mini-base.config.js
export default {
  connectionString: process.env.DATABASE_URL,
  include: ['users', 'posts'], // if set, ONLY these tables get routes
  exclude: ['audit_log'],      // these tables never get routes
}

Use this to keep internal or sensitive tables (audit logs, migration metadata, credentials tables) out of the generated API entirely.

Config file

Instead of passing CLI flags every time, create mini-base.config.js (or .mjs / .json) in the directory you run mini-base from:

js
// mini-base.config.js
export default {
  connectionString: process.env.DATABASE_URL,
  port: 3000,
  schema: 'public',
  include: ['users', 'posts'],
  exclude: ['audit_log'],
  readonly: false,
}

CLI flags always override config file values when both are present. This lets you commit a base config to your repo and still override things like --port locally when needed.
