Hooks (SDK only)

Hooks are the extension point for anything mini-base doesn't do natively — most importantly, authentication and authorization, since mini-base has no built-in auth system.

Hooks are only available through the SDK, not the CLI, since they require passing real JavaScript functions. If you run mini-base as a standalone command, there is no way to attach hooks.
ts
import { createApi, HookRejection } from 'mini-base'

const api = await createApi({
  connectionString: process.env.DATABASE_URL,
  hooks: {
    beforeQuery: (ctx) => {
      // ctx = { table, operation, req }
      // operation is one of: 'list' | 'get' | 'create' | 'update' | 'delete'

      // Example: require a valid session for any write
      if (['create', 'update', 'delete'].includes(ctx.operation)) {
        const token = ctx.req.headers.authorization
        if (!isValidToken(token)) {
          throw new HookRejection(401, 'Authentication required')
        }
      }

      // Example: block a specific operation on a specific table
      if (ctx.table === 'users' && ctx.operation === 'delete') {
        throw new HookRejection(403, 'Deleting users is not allowed')
      }
    },

    afterQuery: (ctx, rows) => {
      // Runs after a successful query, before the response is sent.
      // Return a replacement array to transform the response (e.g. redact fields).
      // Returning nothing leaves the rows unchanged.
      if (ctx.table === 'users') {
        return rows.map(({ password_hash, ...rest }) => rest)
      }
    },
  },
})

beforeQuery(ctx) runs before any SQL executes for a request. Throw a HookRejection(status, message) to reject the request — this is the mechanism for adding your own auth, rate limiting, or any other precondition.

afterQuery(ctx, rows) runs after a successful query, with the rows about to be sent to the client. Return a new array to transform the response (e.g. strip sensitive fields); return undefined to leave it unchanged.

Both hooks receive a ctx object: { table, operation, req }, where req gives you full access to headers, cookies, etc. from the incoming request — this is how you'd read a session token or API key to implement auth.
